# blog-mcp 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Claude Code / Desktop 通过一个本机 stdio MCP 服务操作博客后台的文章、画廊、日记、图床与站点重建，凭证由远端登录换取、可单独吊销。

**Architecture:** `blog-api` 新增 `/api/mcp/*` Bearer 命名空间（`blog-router` 已把 `/api` 转发给它，无需改动），Bearer token 的哈希存进新表 `mcp_tokens`，业务分支直接调用现有 domain 函数。本机 `blog-mcp/` Node 进程用 `@modelcontextprotocol/sdk` 暴露 13 个工具，把每个工具映射成一次 HTTP 调用。

**Tech Stack:** Nitro (cloudflare_module) + D1 + H3、Node 24、`@modelcontextprotocol/sdk` 1.32.2、zod、node:sqlite（仅测试）、esbuild（仅测试）

**Spec:** `docs/superpowers/specs/2026-11-16-blog-mcp-design.md`

## Global Constraints

- 不新增任何 Worker Secret；token 哈希复用 `SESSION_PEPPER`。
- 不新增 KV 绑定；不引入 Paid 计划特性（`npm run check:free-config` 必须继续通过）。
- 不修改 `cloudflare-worker/` 下任何文件。
- 不修改 `nuxt-admin/server/routes/admin/api/[...path].ts`。
- 删除类能力一律不暴露：没有删除文章 / 画廊 / 图床文件的工具或端点。
- token 明文只在下发响应里出现一次，任何地方（日志、`status`、列表接口）只出现 `token_prefix`。
- 工具清单固定 13 个，名字与设计文档 §6.4 完全一致。
- `mcp:read` 与 `mcp:write` 是仅有的两个 scope。

## Review Focus

- **token 在会话中途过期或被吊销**：用户点了工具才失败。期望是一句"凭证已失效，请重新 `blog-mcp login`"，而不是未捕获的 401 异常或 JSON 解析错误。Task 7 的 `formatApiError` 测试覆盖。
- **文章库很大时 `article_list`**：500 篇全文一次返回会撑爆上下文。期望列表只回元信息 + `contentLength`。Task 3 的 `projectArticleList` 测试覆盖。
- **`diary_upsert` 漏填 `isPublic`**：会立刻发到公开站。期望默认不公开。Task 3 的 `withDiaryPublicDefault` 测试覆盖。
- **`image_upload` 收到非图片或超大文件**：期望在发请求前本地拒绝，而不是把任意本地文件变成公开 URL。Task 7 的 `validateUploadPath` 测试覆盖。
- **服务端返回非 JSON（Cloudflare 502 页面、网关错误）**：期望客户端给出状态码和一小段原文，而不是抛 `Unexpected token '<'`。Task 6 的 `parseResponse` 测试覆盖。

`nuxt-admin/scripts/check-mcp.mjs` 用与 `check-gallery-duplicates.mjs` 相同的方式建库：`new DatabaseSync(':memory:')` 依次执行 `migrations/*.sql`，再用一个把 `prepare/bind/first/all/run/batch` 映射过去的 adapter 当作 `BLOG_DB`。

脚本顶部先定义一个可复用的打包助手，供本任务和后续任务使用：

```js
import assert from 'node:assert/strict'
import { readFileSync, readdirSync } from 'node:fs'
import { DatabaseSync } from 'node:sqlite'
import { createRequire } from 'node:module'
import { build } from 'esbuild'
import { createError } from 'h3'

const root = new URL('../', import.meta.url)
const posix = value => value.pathname.replace(/^\/([A-Za-z]:)/, '$1').replace(/\/$/, '')
const alias = { '~~': posix(new URL('.', root)) }

const db = new DatabaseSync(':memory:')
for (const name of readdirSync(new URL('migrations/', root)).filter(n => n.endsWith('.sql')).sort()) {
  db.exec(readFileSync(new URL(`migrations/${name}`, root), 'utf8'))
}
const adapter = {
  prepare(sql) {
    const statement = db.prepare(sql)
    return { bind: (...values) => ({
      first: async () => statement.get(...values) || null,
      all: async () => ({ results: statement.all(...values) }),
      run: async () => ({ meta: statement.run(...values) })
    }) }
  },
  batch: async statements => {
    db.exec('BEGIN')
    try {
      const results = []
      for (const statement of statements) results.push(await statement.run())
      db.exec('COMMIT')
      return results
    } catch (error) { db.exec('ROLLBACK'); throw error }
  }
}

// Nitro auto-imports these in production; keep tests explicit.
globalThis.createError = createError

async function bundleModule(relativePath) {
  const output = await build({
    entryPoints: [posix(new URL(relativePath, root))],
    bundle: true, write: false, format: 'cjs', packages: 'external', platform: 'node', alias
  })
  const module = { exports: {} }
  new Function('require', 'module', 'exports', output.outputFiles[0].text)(createRequire(import.meta.url), module, module.exports)
  return module.exports
}

const mcpToken = await bundleModule('server/domain/mcp-token.ts')
const event = { context: { cloudflare: { env: { BLOG_DB: adapter, SESSION_PEPPER: 'test-pepper' } } } }
```

- [ ] **Step 4: 实现 `mcp-token.ts`**

签名见本任务 Interfaces。实现要点（这些是签名和测试没固定、但必须一致的决定）：

- `isMcpTokenFormat`：`/^bmcp_[A-Za-z0-9_-]{43}$/`。
- `normalizeMcpScopes`：数组里逐项保留 `MCP_SCOPES` 内的值、去重、保持输入顺序；结果为空则回退全量 `['mcp:read','mcp:write']`。
- `normalizeMcpExpiresInDays`：`Number.parseInt`，非有限数回退 30，结果夹在 `[1, 90]`。
- `issueMcpToken`：`label` 必须为非空字符串且长度 ≤ 64，否则 `createError({ statusCode: 400, statusMessage: 'A token label is required (1-64 characters)' })`。token = `MCP_TOKEN_PREFIX + randomToken(32)`，`token_hash = await hashToken(token, getRequiredSecret(event, 'SESSION_PEPPER'))`，`token_prefix = token.slice(0, 12)`，`scopes` 用 `JSON.stringify` 入库。
- `authenticateMcpRequest`：
  1. `authorization` 必须以 `Bearer ` 开头，否则 401 `'Authentication required'`，并 `setResponseHeader(event, 'WWW-Authenticate', 'Bearer')`；
  2. token 必须通过 `isMcpTokenFormat`，否则同样 401（统一文案，不区分原因）；
  3. 查 `mcp_tokens WHERE token_hash = ? AND revoked_at IS NULL AND expires_at > ?`，无行 → 401；
  4. 查 `admin_users` 的 `must_reset`，等于 1 → 403 `'Password reset is required'`；
  5. `requiredScope` 不在行内 scope → 403 `'Insufficient scope: <requiredScope>'`；
  6. 若 `last_used_at` 为空或距今超过 60 秒，`UPDATE mcp_tokens SET last_used_at = ? WHERE id = ?`（节流，避免每次调用写 D1）；
  7. 返回 `McpAuthContext`。
- `listMcpTokens`：按 `created_at DESC, id DESC`，映射为 `McpTokenPublic`（`parseMcpScopesColumn` 解析 `scopes` 列）。
- `revokeMcpTokenById`：`UPDATE ... SET revoked_at = ? WHERE id = ? AND username = ? AND revoked_at IS NULL`；`result.meta.changes === 0` → 404 `'Token not found'`。
- `revokeMcpTokenByHash`：同表，按 `token_hash` 条件更新，不要求 changes。
- `revokeAllMcpTokens`：`UPDATE ... SET revoked_at = ? WHERE username = ? AND revoked_at IS NULL`。
- 时间一律用 `nowIso()`；过期判断是字符串比较，因为都是 ISO-8601 UTC。

图：分发结构

```
parts[0] === 'token'  && len 1 && POST → 签发
```

`POST /api/mcp/token` 的行为：

- body 读取 `{ username, password, label, scopes, expiresInDays }`。
- 先做一次**仅当 Origin 头存在时**的来源校验（CLI 不带 Origin，浏览器会带）：`const origin = getHeader(event,'origin'); if (origin && origin !== getActualRequestOrigin(event) && origin !== getRequestOrigin(event)) throw createError({ statusCode: 403, statusMessage: 'Cross-origin request rejected' })`。理由：这是密码校验入口，不该允许任意网页把它当成密码预言机。
- `verifyAdminCredentials` 失败时：`must_reset` → 403 `'Password reset is required'`；其余 → 401 `'Invalid username or password'`。

`POST /api/mcp/token/revoke`：用 `requireScope(event, 'mcp:read')` 拿到 `ctx`，再 `revokeMcpTokenByHash(event, ctx.tokenHash)`，返回 `{ success: true }`。

`GET /api/mcp/whoami`：`requireScope(event, 'mcp:read')`，返回 `{ username, label, scopes, expiresAt }`。

`GET /api/mcp/tokens`：`await requireAdminSession(event)`，返回 `{ tokens: await listMcpTokens(event, session.username) }`。

`POST /api/mcp/tokens/:id/revoke`：**先** `assertSafeMutation(event)`（Cookie 会话 + 变更请求，必须挡住跨站请求），再 `requireAdminSession`，再 `revokeMcpTokenById(event, parts[1], session.username)`，返回 `{ success: true }`。

```js
function endpoint(method, pathFor, { queryKeys = [], bodyKeys = [] } = {}) {
  return async (args, api) => {
    const query = {}
    for (const key of queryKeys) if (args[key] !== undefined) query[key] = args[key]
    const body = {}
    for (const key of bodyKeys) if (args[key] !== undefined) body[key] = args[key]
    const opts = {}
    if (Object.keys(query).length) opts.query = query
    if (Object.keys(body).length) opts.body = body
    return await api.request(method, pathFor(args), opts)
  }
}
```

```js
export function createMcpServer(api) {
  const server = new McpServer({ name: 'blog-mcp', version: '0.1.0' })
  for (const tool of tools) {
    server.registerTool(tool.name, { description: tool.description, inputSchema: tool.inputSchema }, async (args) => {
      try {
        const result = await tool.run(args, api)
        return { content: [{ type: 'text', text: JSON.stringify(result, null, 2) }] }
      } catch (error) {
        return { isError: true, content: [{ type: 'text', text: formatApiError(error) }] }
      }
    })
  }
  return server
}
export async function serveStdio(api) {
  const server = createMcpServer(api)
  await server.connect(new StdioServerTransport())
}
```

- [ ] **Step 6: 实现 `index.js` 的 CLI**

用 `node:util` 的 `parseArgs`：

```
blog-mcp login  [--label <name>] [--read-only] [--days <1-90>]
blog-mcp logout
blog-mcp status
blog-mcp serve
```

- `login`：交互式读 `username`（普通回显）与 `password`（关闭回显）。关闭回显的做法：`readline.emitKeypressEvents(process.stdin)` + `process.stdin.setRawMode(true)`，逐字符收集，遇到 `\r`/`\n` 结束并 `setRawMode(false)`；期间打印 `*` 不打印字符。拿 `--read-only` 时 `scopes: ['mcp:read']`。成功则 `writeCredentials({ baseUrl, token, tokenPrefix: token.slice(0,12), username, label, scopes, expiresAt })`，打印 `已登录：<label>，到期 <expiresAt>，scope <scopes>`，**不打印 token**。
- `logout`：读凭证 → `POST /api/mcp/token/revoke` → `clearCredentials()`；无凭证时提示并退出码 0。
- `status`：读凭证 → `GET /api/mcp/whoami` → 打印 username/label/scopes/expiresAt 与 baseUrl。
- `serve`：读凭证（缺失则往 **stderr** 写 `尚未登录，请先运行 blog-mcp login` 并 `process.exit(1)`；stdout 留给 JSON-RPC）→ `serveStdio(createApiClient(credentials))`。
- 所有诊断输出一律走 `console.error`；`serve` 模式下 stdout 一个字都不能多。
