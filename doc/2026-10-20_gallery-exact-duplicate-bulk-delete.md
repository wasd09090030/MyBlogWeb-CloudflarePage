# 画廊「完全相同图片」批量删除

## 背景

画廊查重此前只能并排复核并逐条删除。重复导入同一张图片时，逐条点击成本高，因此增加按
「视觉距离 0 / 64」判定的批量删除：每组完全相同图片只保留创建时间最早的一条，其余较晚记录批量删除。

## 判定规则

- 完全相同 = 两个画廊记录的指纹汉明距离为 0，或两条记录解析到同一个图床存储文件。
- 距离非 0 的「疑似重复」（例如 1~8）仍然只出现在人工核对列表中，不参与批量删除。
- 参与分组的记录必须存在画廊 id；读取失败的记录不参与分组。
- 每组按 `created_at` 升序保留第一条；时间相同时保留 id 较小的记录。
- 服务端再次校验顺序：比保留记录更早的记录一律跳过并回报原因，客户端逻辑回退也不会误删最早的一张。

## 删除语义

批量删除复用单条删除已有的保护逻辑，不新增迁移、绑定或密钥：

| 情况 | 行为 |
| --- | --- |
| 独占文件（仅被该重复记录引用） | 先删除图床文件，再在同一 D1 事务中删除画廊记录、停用素材并清理指纹 |
| 文件与保留记录、其他画廊、文章封面或 Hero 共享 | 只删除该重复记录的画廊行，文件保留（返回 409 后走仅记录删除） |
| 外部/无法解析的图床源 | 只删除画廊行（422 后走仅记录删除），不触碰外部文件 |
| 图床删除失败 | 记录保留并回报失败，可重试 |

## 接口

`POST /admin/api/gallery/duplicates/purge`

```json
{ "groups": [ { "keepId": 12, "deleteIds": [18, 25] } ] }
```

- 受管理员会话与同源校验保护，与其他 `/admin/api/*` 一致。
- 单次最多 20 个分组、最多 40 条待删除记录，避免超出 Free 计划每次调用 50 个子请求的限制。
- 返回 `{ deleted, mediaDeleted, recordsDeleted, skipped, failed }`。
- 校验：空分组、保留 id 同时出现在删除列表、跨组重复 id、保留记录不存在都会返回 400。

## 界面

`GalleryDuplicateReview` 在扫描结果上方新增「完全相同图片（视觉距离 0 / 64）」区块：

- 显示组数与可删除张数，可展开核对每组「保留 / 删除」明细。
- 「批量删除较晚的重复图片」需二次确认，确认文案包含组数、张数、删除不可撤销与共享文件只删记录。
- 删除按每批 20 条请求推进，完成后显示删除统计与未完成项，并刷新画廊列表与复核结果。

## 验证

```powershell
npm run check:gallery-duplicates           # 分组规则、接口校验、共享文件、顺序保护
npm run generate
npm run check:gallery-duplicates:browser   # 端到端：预览确认、只删较晚记录、保留最早一条
```

结果：

- 节点检查通过：新增 `exactDuplicateGroups` 用例（保留最早、同文件分组、时间相同时按 id、读取失败排除、
  距离非 0 不分组），以及服务端用例（独占文件删文件、共享文件只删记录、更早记录跳过、参数校验）。
- 浏览器回归退出码 0，`ok: true`；新增用例断言预览仅展示、未确认不发起删除、确认后只删除 #901/#902
  并保留 #900。
- `npm run typecheck` 仍有 11 处既有错误（`diary`、`articles`、`assets`），与本次改动无关，未扩大修复范围。

## 风险与回滚

- 批量删除不可撤销，图床文件被删除后无法通过代码回滚恢复；操作前有确认与明细核对。
- 引用检查覆盖画廊（含隐藏项）、文章封面与 Hero；文章/日记正文中的自由链接不在追踪范围，
  并发写入仍可能在检查之后再引用同一文件。
- 回滚：前端与 API 应一起回滚；本次未改动数据库结构，回滚不涉及数据迁移。
